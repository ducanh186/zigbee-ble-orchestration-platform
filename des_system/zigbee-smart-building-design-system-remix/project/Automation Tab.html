SCRUM-43 · Automation tab

Rules as readable sentences.

The user opens Automation and reads a list. Each rule is a literal when × then sentence — same vocabulary as the user guide, same device IDs as the logs. Creating a new rule means filling in the blanks of that sentence; nothing fancier than that.

The screen is dense enough for repeated demo testing, honest about gateway sync state, and refuses to imply that the app runs the rule locally.

01
List first, form second
Existing rules dominate the screen. A new rule is a single tap into a bottom sheet — the list is never pushed offscreen.
02
Template-led creation
Four MVP templates appear as tappable cards with their plain-text action. No free-form expression builder, no scenes, no schedules.
03
Two status chips, always
Every rule shows sync_status and last_run_status side-by-side. The app never collapses them into one "ok" state.
04
Operator copy
Status values stay UPPERCASE. Device IDs render in JetBrains Mono. No "Welcome back", no emoji.
05
Save button earns its enable
Disabled until rule name + template + trigger + 1+ target are valid. The form hints exactly which piece is missing.
06
Honest about pending
Newly-saved rules start PENDING + NEVER RUN. The app never pretends Gateway acknowledged when it didn't.
