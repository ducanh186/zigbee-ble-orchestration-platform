# Firmware Artifacts

## Overview

All flashable firmware lives in `artifact/` at the repo root. Each device has its own subdirectory with a manifest, flashing instructions, and `.s37` binary files.

```
artifact/
  README.md
  bootloader-uart-xmodem/
    manifest.json
    FLASH.md
    bootloader-uart-xmodem.s37
    bootloader-uart-xmodem-crc.s37
    bootloader-uart-xmodem-combined.s37
  ncp-uart-hw/
    manifest.json
    FLASH.md
    ncp-uart-hw.s37
  Z3Switch/
    manifest.json
    FLASH.md
    Z3Switch.s37              
  Z3Light/
    manifest.json
    FLASH.md
    Z3Light.s37               
```

## What Was Removed from end_devices/ and Why

The following were removed from git tracking to reduce repo size and noise.
They are fully regenerated by Simplicity Studio when you open/build the `.slcp` project.

| Removed | Reason |
|---------|--------|
| `autogen/` | ~55 files per project, regenerated from `.slcp` + `config/zcl/zcl_config.zap` by SLC |
| `.pdm/` | Simplicity Studio internal module state |
| `.settings/` | Eclipse workspace preferences |
| `.uceditor/` | Component editor UI state |
| `.project` / `.cproject` | Eclipse CDT project descriptors; regenerated on import |
| `.projectlinkstore` | IDE navigation history |
| `*.zap~` | Backup files from ZAP configurator |

## Expected Binary Output Types

| Extension | Description | Use |
|-----------|-------------|-----|
| `.s37` | Motorola S-record | Primary flash image for Commander |
| `.hex` | Intel HEX | Alternative flash format |
| `.gbl` | GBL (Gecko Bootloader) | OTA firmware upgrade image |

## OTA Artifact Pipeline Requirements

The current `artifact/` tree documents flashable development images. OTA campaign
support needs a stricter artifact pipeline before Cloud can safely expose
firmware to Gateway.

Minimum OTA artifact requirements:

| Requirement | Purpose |
| --- | --- |
| Real `.ota` or `.gbl` artifact | File Gateway downloads during OTA rollout |
| `manufacturer_id` | Must match the Zigbee OTA image header and target device |
| `image_type` | Selects the correct firmware family |
| `file_version` | Prevents same-version or lower-version rollout by mistake |
| `stack_version` | Documents SDK/stack compatibility |
| `size_bytes` | Detects truncated or wrong file |
| `sha256` | Detects corrupt or replaced file |
| Static file hosting / object storage URL | Gives Gateway a stable internal `artifact.url` |
| SHA256 generation script | Avoids hand-entered hashes |
| Version policy | Blocks unsafe downgrade or duplicate rollout |

Important distinction:

- `.s37` is the normal Commander flash image.
- `.gbl` is the Gecko Bootloader OTA upgrade image.

Do not use an `.s37` file as an OTA campaign artifact unless the Gateway OTA
runtime explicitly supports that format. The OTA contract should normally point
to `.ota` or `.gbl` and include `sha256` plus `size_bytes`.

Reference alignment:

- Silicon Labs documents the normal flow as Commander creating `.gbl` from
  `.s37`, then Image Builder creating a `.ota` image from the `.gbl`.
  https://docs.silabs.com/zigbee/latest/ota-bootload-server-client-setup-zigbee-sdk-v7x-higher/05-ota-image-creation
- In the Silicon Labs Z3Gateway OTA tutorial, the `.ota` file is placed in the
  `ota-files` directory beside the Z3Gateway executable before running OTA.
  https://docs.silabs.com/zigbee/latest/ota-bootload-server-client-setup-zigbee-sdk-v7x-higher/06-zigbee-ota-hands-on-tutorial
