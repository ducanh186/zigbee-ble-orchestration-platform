# Flashing End-Device Firmware

## Prerequisites

- **Simplicity Commander** (CLI or GUI) — included with Simplicity Studio v5, or download standalone from Silicon Labs
- **Hardware**: WSTK Mainboard (BRD4001A) + EFR32MG12 Radio Board (BRD4162A)
- **USB connection** to the WSTK via the J-Link debug port

## Quick Reference

| Device | Type | Flash Command |
|--------|------|---------------|
| Bootloader | NCP Bootloader | `commander flash artifact/bootloader-uart-xmodem/bootloader-uart-xmodem-combined.s37 --device EFR32MG12P332F1024GL125` |
| NCP | Zigbee Coordinator Radio | `commander flash artifact/ncp-uart-hw/ncp-uart-hw.s37 --device EFR32MG12P332F1024GL125` |
| Z3Switch | End Device | `commander flash artifact/Z3Switch/Z3Switch.s37 --device EFR32MG12P332F1024GL125` |
| Z3Light | Router | `commander flash artifact/Z3Light/Z3Light.s37 --device EFR32MG12P332F1024GL125` |
| Z3_Occupancy_Sensor | Router (PIR + Buttons) | `commander flash artifact/Z3_Occupancy_Sensor/Z3_Occupancy_Sensor.s37 --device EFR32MG12P332F1024GL125` |

When more than one J-Link is enumerated, add `--serialno <J-Link serial>` to disambiguate.

## Full Board Setup (from scratch)

### Coordinator board (runs NCP firmware, connects to gateway host via UART)

```bash
# 1. Flash bootloader (must be first)
commander flash artifact/bootloader-uart-xmodem/bootloader-uart-xmodem-combined.s37 --device EFR32MG12P332F1024GL125

# 2. Flash NCP firmware
commander flash artifact/ncp-uart-hw/ncp-uart-hw.s37 --device EFR32MG12P332F1024GL125
```

### End-device boards

```bash
commander flash artifact/Z3Switch/Z3Switch.s37 --device EFR32MG12P332F1024GL125
# or
commander flash artifact/Z3Light/Z3Light.s37 --device EFR32MG12P332F1024GL125
# or
commander flash artifact/Z3_Occupancy_Sensor/Z3_Occupancy_Sensor.s37 --device EFR32MG12P332F1024GL125
```

## Step-by-Step

1. Connect the WSTK board via USB
2. Verify Commander sees the board:
   ```bash
   commander device info
   ```
3. (Optional) Erase the device for a clean state:
   ```bash
   commander device masserase --device EFR32MG12P332F1024GL125
   ```
4. Flash the firmware:
   ```bash
   commander flash <path-to-s37> --device EFR32MG12P332F1024GL125
   ```
5. The device resets automatically after flashing

### What Was Removed from `end_devices/` and Why

These IDE-generated files are excluded from git tracking to reduce repo size. They are fully regenerated by Simplicity Studio when you open/build the `.slcp` project.

| Removed | Reason |
|---------|--------|
| `autogen/` | ~55 files per project, regenerated from `.slcp` + `config/zcl/zcl_config.zap` by SLC |
| `.pdm/` | Simplicity Studio internal module state |
| `.settings/` | Eclipse workspace preferences |
| `.uceditor/` | Component editor UI state |
| `.project` / `.cproject` | Eclipse CDT project descriptors; regenerated on import |
| `.projectlinkstore` | IDE navigation history |
| `*.zap~` | Backup files from ZAP configurator |

Exception: `Z3_Occupancy_Sensor/autogen/sl_simple_led_instances.{c,h}` and `config/sl_simple_led_led1_config.h` are tracked because the LED1 addition is hand-applied — losing them on regenerate would silently drop the second-LED behavior. SSv5 will rewrite them if you re-import; keep an eye on diffs.

### What Is Still Tracked in `end_devices/`

| Kept | Purpose |
|------|---------|
| `*.slcp` | Project configuration — SDK version, components, device, board |
| `*.slps` | Project descriptor — toolchain ID, part ID, board IDs |
| `*.pintool` | Pin assignment configuration |
| `config/` | All component configuration headers + ZCL config (`.zap`) |
| `app.c`, `main.c`, `app/` | Application source code (custom logic) |

### Binary Format Reference

| Extension | Description | Use |
|-----------|-------------|-----|
| `.s37` | Motorola S-record | Primary flash image for Commander |
| `.hex` | Intel HEX | Alternative flash format |
| `.gbl` | GBL (Gecko Bootloader) | OTA firmware upgrade image |

## How to Build Missing Binaries

1. Open Simplicity Studio v5
2. Ensure Gecko SDK 4.5.0 is installed
3. Import `end_devices/<DeviceName>/<DeviceName>.slcp`
4. Build (Release configuration)
5. Copy the `.s37` output into `artifact/<DeviceName>/`

For headless Linux builds (no SSv5), see the per-device `FLASH.md` — `Z3_Occupancy_Sensor/FLASH.md` documents the workspace+Makefile path used in this repo.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| Commander not found | Add Simplicity Studio's `developer/adapter_packs/commander/` to PATH |
| No device detected | Check USB cable, try different port, verify J-Link drivers |
| Flash verification failed | Try mass erase first, then re-flash |
| NCP not responding after flash | Ensure bootloader was flashed first |
| `--no-warn-rwx-segments` linker error | Building with GCC 10 ld; force-set PATH to bundled `~/SimplicityStudio_v5/developer/toolchains/gnu_arm/12.2.rel1_2023.7/bin` |
